## Why this package is blocked rather than complete

Creating a Supabase project requires dashboard access to the account,
an organisation, a region choice and a plan decision. It cannot be
performed from the repository, and it is not something to be done on the
account owner's behalf.

What is delivered is everything that *is* in the repository's power: the
runbook that makes the provisioning fast and ordered, the configuration
that selects an environment, and the checklist the acceptance criteria
are verified against. **The criteria are deliberately left unticked.**
Marking this package complete because its documentation exists would put
a false green against the prerequisite that guards every schema epic in
the roadmap.

## Findings

**1 · No migration ledger, and this is the last comfortable moment.**
Nothing records which migrations have been applied to which environment.
`0001_init.sql` says to paste it into the SQL Editor, and
`supabase/diagnostics/CHECK_STATE.sql` exists specifically because state
must be inferred from the catalog afterwards. Seventeen hand-applied
files is tolerable. Epics 01–14 introduce far more, against two
environments, where "which of these has staging already had?" becomes
unanswerable by inspection. **Flagged, not solved** — building a ledger
is not this package's scope.

**2 · No Supabase CLI.** Migrations are applied by pasting SQL into the
dashboard. Seventeen files in strict order, by hand, with no ledger, is
an error-prone operation that the runbook mitigates but does not fix.
Installing the CLI is a dependency addition outside this package.

**3 · The migration set has never been applied from empty.** Every
migration has only ever run incrementally against one long-lived
database. Whether the seventeen reconstruct that database from nothing is
genuinely unknown. This package's provisioning step is the first test of
it, and a failure there is a defect in the migration set rather than a
staging problem — which is why the runbook says to stop and report at the
first failure rather than work around it.

**4 · `.env.local.example` omits `ANTHROPIC_API_KEY`.** The AI endpoints
require it and the example does not mention it, so a new developer's
first AI call fails with no guidance. Real but unrelated to environment
selection; not fixed here.
