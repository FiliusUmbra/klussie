## Notes

**`allowJs: true`, `checkJs: false`.** The existing JavaScript is
*visible* to the compiler — so a future `.ts` file can import it — but is
not type-checked. This is what makes incremental adoption possible
without a wall of errors on day one. It also means `tsc --noEmit` has
inputs today, avoiding a "no inputs found" failure while zero `.ts` files
exist.

**`strict: true` from the start.** Strictness costs nothing now, when
there is no TypeScript to fix, and is painful to adopt later. New code
starts strict; old code is unaffected because it is not checked.

**Type-aware linting deliberately not enabled.** `typescript-eslint`'s
type-aware rules require a full type-check per lint run, which would
noticeably slow CI to catch what `npm run typecheck` already catches.
Revisit if a class of bug appears that only type-aware rules find.

**TypeScript 6.0 and `typescript-eslint` 8.** Installed at latest against
ESLint 10. Compatibility was verified by probe rather than assumed, since
ESLint 10 is recent enough that plugin support is not a given.

## Finding raised during implementation

**ESLint was linting generated, untracked files, and CI would not have
noticed.**

Extending ESLint to `**/*.{ts,tsx}` made it match
`marketing/.astro/content.d.ts` and `types.d.ts` — Astro's *generated*
type declarations, in a separate project with its own `package.json`,
covered by `marketing/.gitignore`. Five errors, all in code nobody wrote.

The sharp part: **those files are gitignored, so a fresh checkout does
not contain them.** CI would have been green while `npm run lint` failed
on a developer machine. A gate that disagrees with local reality is worse
than no gate, because it teaches people to distrust it.

Fixed by adding `**/.astro` to `globalIgnores`, matching the existing
`dist` precedent — generated output is not linted. Verified that
marketing's *tracked* source is still linted, so no coverage was lost.
