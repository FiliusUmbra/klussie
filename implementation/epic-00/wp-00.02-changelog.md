## Notes

**The changelog starts here and does not reconstruct history.**
Backfilling 40+ prior commits would be scope expansion, and a
reconstructed changelog is a worse artefact than an honest one — it reads
as authoritative while being someone's later guess at what mattered. The
file says where earlier history lives instead.

**Keep a Changelog format, adapted to epics.** The roadmap's unit of
delivery is the epic, not a semantic version, and the platform has no
release versioning yet. So entries group under epics rather than version
numbers, with an `Unreleased` section for work in flight. If versioned
releases arrive later, the format accommodates them without restructuring
— which is why a conventional format was chosen over an invented one.

**Why the standards doc rather than `ENGINEERING.md`.** The roadmap
declared `docs/engineering/ENGINEERING_STANDARDS.md` as the file to
change. It is also the right home: it owns enforceable rules, and "record
what changed" is a rule. `ENGINEERING.md` describes workflow and already
points at the roadmap's §9 documentation obligations, which include the
changelog — no third file needed.

**Branched from WP 00.01 rather than `main`.** `ENGINEERING.md` §5 says
to branch from `main`, but `main` has neither WP 00.01 nor the frozen
architecture, both of which are approved and unmerged. Stacking keeps
history linear and avoids a false conflict at merge. Recorded as a
deliberate deviation; the general rule stands once Epic 00 merges.
