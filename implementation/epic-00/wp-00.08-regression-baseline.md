## What the baseline consists of

**1 · A definition** (`TESTING.md` §1). Six categories of behavioural
regression, the sixth being **silent fixes** — a known defect corrected
without being declared. That category exists because this project has
already been bitten by it: the Engineering Health sprint found twelve
places rendering literal escape text and deliberately preserved them,
since fixing them would have changed what a customer reads inside a
refactor that promised not to.

**2 · A complete flow inventory** (§5). Fifty-nine flows across
authentication, customer intake, the request-to-review loop, My Home,
professional surfaces, messaging, profile, and cross-cutting concerns.
Each is either automated or listed for manual verification.

**3 · An honest coverage map** (§4). 404 existing tests are heavily
skewed: `src/lib` and the homepage are strongly covered; **31 user-facing
components have no render test at all**. The baseline records that gap
rather than pretending to fill it — closing it is separate tracked debt
in `MASTER_CONTEXT.md` §12.

**4 · Pinned known defects** (§6, `knownDefects.test.js`). Fourteen
literal escape sequences across seven files, counted by sequence:
`u20ac`×9, `u2022`×3, `u2013`×1, `u00b7`×1. Nine of them are euro signs,
in invoice totals, quote prices and the flexi tax tracker — where a
customer is most likely to see one.

**5 · A self-enforcing inventory** (`baselineCoverage.test.js`).

## Decisions made

**Render tests for the 31 uncovered components were deliberately not
written here.** The roadmap tracks that as a separate Phase 2 item
(*"Add render tests per feature folder"*), and the acceptance criterion
for this package is completeness of the **record**, not of the
automation. Absorbing a multi-day testing effort into a baseline package
would have delayed the artefact every later epic needs.

**Defects are pinned by sequence count, not per file.** Moving a
component between files is a refactor and should not fail the baseline;
fixing or introducing an occurrence changes what a customer reads and
should.

**The escape pattern is built from character codes**, not written
literally — a source file containing the sequence is exactly what the
test searches for, so a literal would make the test find itself.

**`awaiting_pro` is not re-pinned.** `requestStatus.test.js` already
covers the rule. `TESTING.md` §6.2 records that what the customer *sees*
remains unprotected, because those surfaces have no render tests.

## Rollback

Delete `src/__tests__/regression/` and `docs/engineering/TESTING.md`. No
application code, no data, no dependency.

## Findings

**1 · The coverage skew is sharper than the debt register implied.**
`MASTER_CONTEXT.md` §12 describes missing render tests for the extracted
feature components. Measured: **31 of 53 user-facing components have
none**, and they include the entire request→quote→accept→complete→review
loop. C17 — accepting a quote — is one transaction doing four things, is
the highest-consequence flow in the platform, and is verified by hand
only.

**2 · The literal-escape defect was completely unprotected.** Fourteen
customer-visible strings, recorded in a debt table that nothing enforced.
Any future package could have "tidied" them and the diff would have
looked like an improvement.
